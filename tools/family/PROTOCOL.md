# 가족 relay HTTP 계약 v1

`app/src/main/java/dev/carevisit/app/HttpFamilyLink.kt`와 호환하는 로컬 시연 계약이다. Python 3.9 이상 표준 라이브러리만 사용한다. 공개 운영에는 **HTTPS + 실제 사용자 인증**이 필요하다. HTTP 시연에서는 신뢰하는 사설 Wi-Fi와 허구 데이터만 사용한다.

```sh
python3 tools/family/relay.py --host 127.0.0.1 --port 8765
# 휴대폰 접속도 허용할 때: --host 0.0.0.0 (방화벽은 사설 LAN만 허용)
cd tools/family
python3 -I -m unittest
```

차량 URL: `http://10.0.2.2:8765`. 휴대폰 URL: `http://<노트북 LAN IP>:8765/#<token>` 또는 `/`에서 토큰 입력. 10.0.2.2는 에뮬레이터 전용 주소이므로 휴대폰에서는 노트북 LAN IP로 바꾼다.

## 연결과 인증

차에서 별도 공유 동의 후 만든 128비트 난수의 소문자 hex 32자 토큰을 사용한다. 짧은 숫자 PIN으로 축약하지 않는다. 모든 `/api/*` 요청은 `Authorization: Bearer <token>` 헤더가 필요하다. URL fragment는 서버에 전달되지 않으며 페이지가 읽은 즉시 주소 표시줄에서 제거한다. 쿠키, localStorage, 계정, 외부 서비스, QR 서비스는 사용하지 않는다. 새로고침 시 코드를 다시 입력한다.

첫 `POST /api/message`(통상 `가족 연결됨` 상태)가 세션을 만든다. 토큰을 아는 사람은 이 세션을 읽거나 쓸 수 있는 시연용 capability 모델이다. relay는 승인 여부를 독립적으로 확인할 수 없으며 차의 명시적 동의/전송 확인을 신뢰한다. 차/가족 권한을 분리하는 운영용 인증 모델은 아니다.

## 요청과 응답

JSON은 UTF-8, POST는 `Content-Type: application/json`과 정확한 `Content-Length`를 보낸다. chunked 요청은 지원하지 않는다. 성공은 모두 HTTP 200이다.

| 메서드·경로 | 요청 | 응답 |
|---|---|---|
| `GET /` | 인증 불필요 | 한국어 가족 HTML |
| `POST /api/message` | `{"id":"고유문자열","kind":"memo","text":"승인한 내용"}` | `{"ok":true}` |
| `GET /api/session` | 없음 | `{"messages":[{"id":"…","kind":"memo","text":"…"}],"remainingSeconds":86400}` |
| `POST /api/reply` | `{"text":"나왔어"}` 또는 `{"text":"잘 받았어"}` | `{"ok":true}` |
| `GET /api/replies?after=0` | after는 마지막 수신 ID, 생략 시 0 | `{"replies":[{"id":"1","text":"나왔어"}]}` |
| `DELETE /api/session` | 없음 | `{"ok":true}`; 없는 세션도 성공 |

메시지는 정확히 id/kind/text만 허용한다. kind는 `memo`, `briefing`, `status`. status의 text는 `가족 연결됨`, `정문 도착`, `주차 중`만 허용한다. 위치 필드와 대화 원문 종류는 허용하지 않는다. 자유 메모에서 개인정보를 자동 탐지하는 기능은 없다. 차가 승인된 텍스트만 보내야 한다.

동일 id는 현재 보관 메시지 내에서 중복 제거한다(먼저 받은 내용 유지). replies는 삭제하지 않고 커서 이후 항목을 반환한다. ID는 세션별 1부터 증가하는 십진 문자열이다. 앱과 웹은 약 5초마다 조회한다. relay 수신 성공은 차량 음성 재생 완료를 뜻하지 않는다.

| 오류 | 뜻 |
|---|---|
| 400 | JSON/필드/크기 규칙/커서/Content-Type 오류, 세션 용량 초과 |
| 401 | 토큰 누락 또는 형식 오류 |
| 403 | 다른 Origin의 브라우저 요청 |
| 404 | 미연결·삭제·만료 세션 읽기/답장, 없는 경로 |
| 410 | 삭제·만료된 토큰으로 다시 메시지 전송 |
| 413 | Content-Length가 32 KiB 초과; 본문을 읽기 전에 거부 |

## 보관과 한도

- 최초 메시지 수신 시점부터 **24시간 절대 TTL**. 전송·조회·답장으로 연장되지 않는다. 접근 시 즉시 만료 처리, 미접속 데이터도 30초 간격으로 정리한다. 따라서 미접속 메모리 제거에는 최대 약 30초 오차가 있다.
- 삭제 즉시 건강 텍스트와 답장을 지운다. 재전송 차단용 토큰만 삭제 시점부터 24시간, 만료 시에는 원래 만료 시점부터 24시간 추가 보관한다. 그 뒤 또는 relay 재시작 후에는 과거 토큰 재사용을 막을 수 없으므로 차에서 새 토큰을 만든다.
- 세션+차단 토큰 최대 512개. 없는 토큰의 DELETE는 새 항목을 만들지 않는다. 동시 처리 32개, 소켓 읽기 제한 5초.
- 요청 본문 최대 32,768 bytes, id 1–64자, text 1–16,000자. 실제 UTF-8 JSON 크기 제한도 적용하므로 긴 한국어는 문자 한도보다 먼저 제한될 수 있다.
- 세션 메시지는 최신 30개이면서 직렬화 JSON 합계 96 KiB 이하. 넘으면 오래된 항목부터 제거한다. 앱의 응답 읽기 한도 128 KiB 안에 들어간다. 답장은 최신 100개만 보관하므로 장시간 오프라인이면 오래된 답장은 놓칠 수 있다.
- 데이터 파일·접근 로그를 쓰지 않는다. 재시작/종료하면 모든 세션이 사라진다. 웹은 건강 텍스트를 textContent로 표시하고 캐시를 금지한다. 토큰을 가진 사용자의 복사/캡처까지 막지는 않는다.
- 웹과 API는 동일 origin이므로 CORS 헤더가 필요 없다. Origin이 없는 Android 호출과 현재 HTTP Host와 일치하는 Origin만 허용한다. HTTPS 역방향 프록시를 도입할 때는 이 정책과 인증을 함께 변경해야 한다.
