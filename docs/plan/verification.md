# 기획서 후속 수정 확인

2026-11-15. 이전 초안 확인 기록을 현재 생성물 기준으로 갱신했다.

- 공식 원본 양식은 수정하지 않았다. 개인·1명·앱명만 입력하고 개인정보·서명은 비워 둔다.
- `python3 -I tools/plan/build_docx.py` 및 LibreOffice `--preview` 성공.
- `python3 -I tools/plan/check_layout.py` 통과: 8개 박스 첫 문단 keep 끊기, 바깥/중첩 행 분할, 이미지 keep 종료, 4개 캡처 높이, 영상/APK 안내, XML 파싱.
- 실제 에뮬레이터 캡처 4장, 여정 흐름도, 신규 인터뷰 구조도를 포함했다. 캡처 자체는 편집하지 않았다.
- 구조도는 고정 질문 칸 → 발화 원문/ID → 고정 서식 결과 → 선택 LLM/결정적 검사로 구성한다. `Korean.kt`의 PolishGuard를 다시 읽어 토큰 내용·순서 검사와 길이 제한을 대조했다.
- 새 웹 근거는 공식 자료 2건이며 `evidence.md`에 게시일·열람일·숫자 범위·URL을 기록했다. 박스 2·6·7에 연결했고 MAU 비율은 계속 가정으로 표시했다.
- 시연 영상 `docs/demo/jinryo-donghaeng-demo.mp4`는 의뢰 시 녹화 중이었고 파일도 아직 없어 녹화 중/예정으로 표시했다. 약 2~3분, 화면 녹화·자막·무음, 인터뷰→하차→브리핑→가족 답장 설명을 넣었다. `apk/`의 release APK와 LICENSE/NOTICE.md도 안내했다.
- 앱 APK·실기 동작을 이번 PLAN 작업에서 새로 검증하지 않았다. 앱 테스트 수를 추가하지 않았다.
- 문서 안에는 저장소 URL·계정명·개인 실명을 추가하지 않았다. 도구/문서 소유 범위 밖 소스는 수정하지 않았고 커밋하지 않았다.
- 현재 페이지 수와 파일 해시는 `build-verification.json`. Word 원인 조사·수정 세부는 `word-layout.md`.

Microsoft Word는 이 환경에 없어 실제 Word 페이지 계산은 제출 PC에서 최종 확인해야 한다. LibreOffice에서 제목과 박스 7 첫 본문이 같은 페이지에 놓이는지, 그림과 캡처가 잘리지 않는지 확인했다. 캡처나 영상 안내를 추가 수정하면 다시 빌드한다.
