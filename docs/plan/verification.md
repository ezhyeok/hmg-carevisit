# 심사 리뷰 개선 확인 — 2026-11-15

DOC 담당 범위만 수정했다. CORE/UI의 런타임 구현·테스트는 각 담당 범위다. 변경 요청·인계는 `docs/coord/requests.md`에 남겼다. 커밋하지 않았다.

## 반영한 항목

1. **심사자 실행:** README 맨 앞에 제출 APK 설치 → 현재 사용자 CAR_SPEED 허용 → `am start -S --es demo visit` → VC 시나리오 순서를 넣었다. source build는 아래로 옮겼다. APK manifest를 직접 읽어 package/version을 확인하고 크기·SHA-256을 기록했다. Android 빌드·release APK·에뮬레이터 시연은 2026-11-15 LEAD 검증으로 명시했다. 기존 APK와 이번 소스 개선의 재검증은 구분한다.
2. **REAL/MOCK:** README·기획서·노트북 안내·영상 자막에서 실제 TTS SDK/VC/UX 제한과 모의 STT/목적지·도착/시간 이동/가족 답장을 나눴다. 가족 HTTP 경로는 demo=off로 별도 안내한다. TTS 연결은 실제 들리는 출력 품질의 증거가 아니다.
3. **검증·사업:** 확보 사용자 0명, 10가구 모집 계획, 모집 경로·비교 실험·통과 기준을 PLAN으로 표시했다. MAU 100명 계산은 모든 입력이 미검증인 예시다. 지불자는 운영기관, 과금 단위는 월 활성 차량이라는 가설이며 가격·계약은 미확보다.
4. **차별성:** 음성 메모/메신저/진료동행을 시작 부담·병원 이동 연결·차량 맥락·주행 제한·재사용의 5축으로 비교했다. 특정 경쟁 제품의 기능 실사 표가 아닌 수동 사용 방식 비교로 한정했다.
5. **공격 가능한 주장:** 도어 열림≠실제 하차, 알림은 서비스 실행 중, 한 돌봄 대상 프로필, 원문 보존=STT 인식문 추적, 승인 글에 개인정보 포함 가능을 명시했다. 649→23,048은 한국경제 전재본의 공공 서비스 건수로 한정하고 성장 배수·시장 규모로 쓰지 않았다.
6. **소스와 대조:** 이번 CORE의 `PolishGuard` 공백 외 문자 동일성 검사, `VisitMachine` 귀가 누적 주행 60초 대기, 약·예약 읽기 확인/1회 정정 구현을 읽고 본문·그림에 반영했다. 기존 APK·녹화가 추가 동작의 증거인 것처럼 쓰지 않았다. SPEC의 649 수치 범위·공백 검사·단일 대상·귀가 대기·REAL/MOCK 반영도 확인했다. ARCHITECTURE의 남은 동기화 요청은 CORE에게 전달했다. 시연 시간 이동은 실제 60초 대기를 검증한 것으로 계산하지 않는다.

## 생성·검증

- `python3 -I tools/plan/build_docx.py --preview docs/plan/preview`: DOCX·검토 Markdown·그림·PDF·페이지 PNG 생성. 원본 양식은 수정하지 않았다. 참가 개인·1명·앱명만 채우고 개인정보·서명은 빈칸이다.
- `python3 -I tools/plan/check_layout.py`: 검사 1종 실행 통과. 8개 박스 시작, 분할 가능한 긴 행·중첩 표, 이미지 keep 체인의 종료, 캡처 4장 높이, 영상/APK 안내, XML 파싱 확인.
- `python3 tools/laptop/update-label.py --check`: 검사 1종 통과. 처음에는 잘못된 작업 폴더의 경로로 실행해 실패했고 저장소 루트에서 다시 실행해 통과했다.
- `(cd tools/laptop && python3 -I -m unittest)`: **12개 테스트 통과**. 런타임 코드 변경은 없고 앱/코어 테스트 수를 새 결과처럼 기재하지 않았다.
- 영상 JSON: **11개 구간**의 파일·시작/끝·배속·순서가 HEAD와 같고 caption/sub/lines만 바뀌었음을 대조했다. 타이틀 **8줄**은 실제 지정 폰트로 너비를 측정해 1920px 화면 여백 안에 들어감을 확인했다. MP4 자체는 이번 DOC 작업에서 재렌더하지 않았다.
- `git diff --check`: 담당 파일 공백 오류 없음. 원본 캡처 4장은 편집하지 않았다. 캡처 표시 높이만 6.6cm로 줄여 페이지 끝에서 캡션이 떨어지는 현상을 피했다.
