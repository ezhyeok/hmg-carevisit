# 디자인·문제 정의 개편 확인 — 2026-11-15

이번 편집은 `tools/plan/**`, `docs/plan/**`와 생성 DOCX만이다. 앱 코드·README·영상·자막·APK는 수정하지 않았다. 커밋하지 않았다. 직전 사업성·근거 보강 기록은 [이력](history/2026-11-15-business-evidence.md)에 보관했다.

## 박스별 반영

- **1 — 한눈에 보는 소개.** 쉼표의 파란 강조색·둥근 카드·짧은 설명을 재사용했다. 왼쪽은 짧은 진료·놓친 질문·가족에게 되풀이하는 설명, 오른쪽은 가는 길 인터뷰 → 진료 메모 → 오는 길 브리핑 → 승인 후 가족 공유다. 아래에 차량 신호로 대화 시점을 정한다는 가치 문장을 배치했다.
- **2 — 누구의 어느 순간인가.** 부모님을 정기 진료에 모시는 운전자의 준비·전달 공백을 먼저 제시했다. 23,048건(2025; 2021년 649건), 진료 5분 미만 응답 55.0%, 65세 이상 20.3%(2025)를 KeyNumbers 타일로 바꿨다. 근거는 기존 [1][2][4]이며 새 통계를 추가하지 않았다. 반복 진료·가족 지원 공백은 짧은 표로, 왜 차인지는 세 항목으로 정리했다. 기존 5축 비교표를 유지했다.
- **3 — 실제 화면으로 기능 설명.** 첫 주행 캡처에 현재 질문·대화 상태·짧은 응답·시연 표시·주행 제한의 다섯 주석을 붙였다. 실제 캡처는 ‘말하는 중’이므로 ‘듣는 중’이라고 바꾸어 설명하지 않는다. 기능 표는 사용자 가치 / 차량 신호·API의 두 열로 압축했다. 동의·보관·공유·의료 판단 금지·선택 LLM의 경계를 유지했다.
- **4 — 네 장면 스토리보드.** 출발 전 / 가는 길 / 진료·정문 합류 / 오는 길·가족으로 정리했다. 차량·앱의 동작과 사용자가 듣고 보는 것을 구분했다. 진료실을 녹음하지 않으며 문 열림은 하차·진료 완료를 확정하지 않는다는 설명을 남겼다.
- **5·7 — 시각 일관성.** 인터뷰 구조도는 그림 4, 기존 네 캡처 묶음은 그림 5로 번호를 맞췄다. 그림 3은 스토리보드다. REAL/MOCK 경계, 아홉 출처, 사업성 가정, 제출 영상·APK 안내는 유지했다.

‘3분 진료’와 ‘20–40분이 유일한 조용한 시간’은 기존 근거에서 확인되지 않아 쓰지 않았다. 대신 확인된 진료시간 응답과 함께 탄 시간에 대화를 정리한다는 사용 상황을 썼다. 질문 누락·전달 부담의 빈도나 제품 효과를 측정값처럼 제시하지 않는다.

## 생성·레이아웃 검사

- `python3 -I tools/plan/build_docx.py --preview docs/plan/preview` 성공. **LibreOffice 11쪽**이며 페이지 PNG 전체 배치와 2·3·4쪽의 본문을 확인했다. 박스 7 제목과 첫 내용은 함께 7쪽에서 시작한다.
- `python3 -I tools/plan/check_layout.py` 성공. 8개 박스의 시작, 내부 표 행 분할, 이미지·캡션 keep 종료, 모든 그림 높이 8cm 이하, 기존 네 캡처, XML과 영상·APK 경로를 검사했다.
- 첫 생성물에서는 Annotated 블록의 기본 `cantSplit` 때문에 기존 레이아웃 검사가 실패했다. Annotated 행과 Storyboard 제목·머리 행의 분할 잠금을 풀고, Storyboard 제목의 `keepNext`를 종료했다. 표형 그림 앞 소제목도 다음 표 전체를 끌고 가지 않게 했다. 수정 후 검사와 재생성을 통과했다.
- 기존 네 캡처는 HEAD와 바이트 비교해 불변을 확인했다. 원본 양식의 03 개인정보 동의서 XML도 동일하다. 스크린샷이 없을 때의 별도 임시 문서 생성도 성공했다.
- 출처 9개·기존 열람일·경제성 산술·허용 편집 범위·`git diff --check`를 확인했다. 최종 문서 해시와 페이지 수는 [build-verification.json](build-verification.json)에 기록했다.
- 앱 동작을 바꾸지 않아 앱/코어 테스트와 count_tests는 실행하지 않았다.

Microsoft Word 실행 환경은 없어 실제 Word 쪽수는 미확인이다. 목표는 13쪽 이하이며, LibreOffice 11쪽과 8cm 이하 그림·표 행 분할로 여유를 두었다.
