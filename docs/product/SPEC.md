# 병원 방문 동행 제품 사양

앱 이름의 유일한 원본은 `app/src/main/res/values/strings.xml`의 `app_name`이다. 패키지는 `dev.carevisit.app`, 순수 Kotlin 모듈은 `visit-core`다.

## 목적과 근거

성인 자녀가 부모님을 모시고 병원으로 가는 20–40분 동안 의사에게 물어볼 것을 음성으로 준비한다. 돌아오는 길에는 들은 말을 그대로 기록하고, 확인한 브리핑을 가족에게 공유한다. 기기 안의 마이크·TTS와 차량 기어·도어·내비 신호를 사용한다. 실명 대신 어머니/아버지/부모님/보호자 호칭만 사용한다.

기획 근거(의뢰 제공 인용): **서울 병원안심동행 서비스 이용 649건(2021) → 23,048건(2025), 한국경제.** 이 수치를 앱의 효과나 잠재 사용자 수로 환산하지 않는다. 기사 원문 주소·제목은 제공되지 않았으며 별도 확인이 필요하다.

## 바꿀 수 없는 원칙

1. **의료 판단 금지.** 진단, 분류·중증도 판단, 약·용량 제안, 증상 해석을 하지 않는다. 질문과 출력 구조는 고정되어 있다. 건강 내용은 `SlotValue.verbatim`과 그 원문 `Utterance.id`로만 채운다. 예약의 파싱 결과에도 원문 발화 ID가 있다. 저장 시 `Visit.traceable()`로 연결이 끊긴 기록을 거부한다. 약 이름의 정확성도 검증·해석하지 않는다.
2. **동의 없이 건강 정보 기록 금지.** 개인정보 보호법 제23조의 민감정보에 해당하는 건강 정보를 다루므로 별도의 명시적 수집·보관 동의를 받는다. 첫 인터뷰 전에 현재 설정된 보관 일수를 넣은 고정 동의 안내를 읽고 분명한 긍정 응답을 받아 동의 시각·문구 버전을 저장한다. 주차 화면에는 전체 안내와 동의/거절 버튼을 제공한다. 침묵·불명확한 답·건강 이야기는 동의로 간주하지 않는다. 동의 응답 자체는 건강 원문으로 저장하지 않는다. 동의 전 탐지한 병원 이름·좌표도 메모리에서만 유지하며 파일에는 세션/병원 목록을 쓰지 않는다.
3. **기기 안의 보관과 삭제.** 앱 내부 `filesDir/visits.json`만 사용하고 백업을 끈다. 기본 보관 기간은 180일이며 1–365일로 제한한다(화면은 30/90/180/365일 프리셋). 시작, 매초 틱, 설정 변경 시 만료 기록을 삭제한다. 전체 삭제 한 번으로 진행 중 기록, 완료 기록, 동의와 연결 토큰을 제거한다. 물리 저장매체의 포렌식 삭제를 주장하지 않는다.
4. **가족 공유는 두 단계 동의.** 설정의 별도 가족 공유 동의 이후에도 메모/브리핑마다 정확한 보낼 문구를 읽고 “가족에게 보낼까요?”에 긍정 응답을 받아야 한다. 고정 상태(정문 도착/주차 중/가족 연결됨)는 설정 동의의 대상이다. `FamilyLink`에는 승인 DTO의 id/kind/text만 전달한다. 위치·좌표·원시 대화 목록·실명 필드는 없다. 동의 철회는 실행 중 효과를 취소하고 relay 삭제를 시도한다. 이미 전달된 정보를 사용자가 복사한 경우까지 삭제할 수 있다고 주장하지 않는다.
5. **LLM 없이 완전한 제품.** `Templates.memo/briefing`만으로 기록이 완성된다. 옵션 문장 정리는 기본 끔, ON_DEVICE만 사용하며 8초 후 원문으로 돌아간다. `PolishGuard`는 길이 1.5배 이하와 모든 문자/숫자 토큰의 순서·동일성, 신체어 보존을 검사한다. 문장부호·띄어쓰기 외의 변경은 거부한다. 새 숫자·날짜·약 이름·신체어뿐 아니라 부정 표현 삭제나 용량 순서 바꾸기도 통과하지 못한다. 이는 유창성보다 사실 보존을 택한 의도적 제한이다.

알람처럼 들리는 말을 입력해도 의학적 평가를 하지 않는다. “가슴이 아파”, “숨이 차”에는 다음 고정 문장만 추가할 수 있다.

> 불편이 심하면 진료 전에 병원에 바로 말씀하세요

정확한 요청 “119”, “119 불러줘”, “119에 전화해”, “응급실 가자” 등에만 아래 고정 문장을 말하고 대화를 일시 중단한다. 앱이 대신 전화하거나 경로를 긴급 변경하지 않는다.

> 응급 도움을 원하시면 119에 직접 연락하세요. 이 앱은 전화하거나 상태를 판단하지 않습니다.

## 상태와 여정

`IDLE → WAIT_SAFE → HEALTH_CONSENT(필요 시) → OFFER_PRE → PRE → MEMO → AT_HOSPITAL → OFFER_POST → POST → BRIEFING → SHARE(가족 연결 시) → REMINDER(유효 날짜 시) → DONE`.

중단/재시작은 `RECOVERY`로 이동한다. 자동으로 남은 답을 추정하거나 미완료 공유를 재전송하지 않는다. 주차 후 이어가면 저장된 질문을 새 요청 ID로 다시 묻고, 폐기하면 부분 세션을 버린다. 연속으로 두 번 재시작해도 질문과 원래 단계가 보존된다.

### 가는 길

- 내비 목적지 이름에 병원/의원/의료원/클리닉/한의원/치과/보건소가 있거나 저장한 병원 이름과 일치하면 시작한다. 수동 “병원 가는 길” 버튼/음성도 같은 여정을 만든다.
- 기본은 D이고 차속 0.5m/s 초과로 누적 60초 움직인 뒤 한 번만 권한다. TBT를 사용하지 않는 대안이며 회전 구간을 직접 판별했다고 주장하지 않는다. 주차 중 사용자가 준비 시작을 명시하면 바로 묻는다.
- 동의 후 “어머니 진료 가시는 길이죠? 의사 선생님께 드릴 말씀을 차에서 정리해 둘까요?”를 묻는다. 거절한 여정에서는 반복 권유하지 않는다.
- 같은 병원의 직전 기록에 다음 확인 사항 또는 약 변경 원문이 있으면 먼저 “지난번에 ‘원문’이라고 기록하셨는데, 그 뒤로 어떠세요?”를 묻는다. 특정 약을 바꿨다고 앱이 추정하지 않는다.
- 주 증상 → 언제부터 → 어떨 때/어떻게 → 드시는 약/변경 → 꼭 물어볼 것 순서. 질문은 최대 5개까지 “또 있어”로 추가한다.
- 각 질문의 침묵·불명확 응답은 한 번 재질문하고 이후 건너뛴다. “넘어가/다음/몰라/없어”도 건너뛴다. `응/네/어/그래`, 띄어쓰기 누락, 끝말 잘림을 좁은 allowlist로 처리하며 “어지러워” 같은 문장을 긍정으로 오인하지 않는다.
- 기간은 사흘/이틀/열흘/일주일/한 달/지난달/어제 및 숫자 기간을 정규화하되 원문을 항상 남긴다.
- 메모는 주차 시 큰 글씨로 표시하며 “물어볼 것”의 발화 ID별 체크리스트를 제공한다.

### 정문 하차와 합류

- 내비 도착 이벤트 또는 목적지 200m 내에서 길안내가 종료된 것을 도착 후보로 삼는다. 경로 취소를 어디서나 도착으로 해석하지 않는다. 주차 화면의 수동 도착 확인도 가능하다.
- 후보가 있고 기어 P이면 병원 체류를 시작한다. 동승석 앞 오른쪽 문이 열리면 “천천히 내리세요.”를 말한다. 가족 공유가 켜져 있으면 지정된 가족 화면 안내를 붙인다. 메모 공개 자체는 별도의 공유 확인을 통과해야 한다.
- P 화면에서 “정문에서 내려 드리고 주차 후 합류”를 선택하면 고정 “주차 중” 상태를 보낸다. 이 모드에서 가족 웹의 “나왔어”를 받으면 “어머니가 정문에 나오셨대요”를 말한다. 같은 reply ID는 중복 처리하지 않는다.
- 좌석 점유, 시트 이동/열선, 창문·도어 제어는 사용하지 않는다. 승하차 안내는 승객 감지나 실제 하차 완료 판정이 아니다.

### 오는 길과 다음 진료

- 병원 도착 P 이후 15분 이상 지나 P→D가 되면 귀가 기록을 한 번 제안한다. FusedLocation 기반 새 여정 판정은 사용하지 않는다. 짧은 정차에서 곧바로 귀가 질문이 나오지 않게 한 기준이다.
- 의사 말씀 → 약 변경 여부/원문 → 검사·예약 → 주의 말씀 → 다음에 확인할 것. 약 변경이 아니면 그 “아니요” 응답도 원문으로 보존한다.
- 날짜는 Asia/Seoul의 오늘 기준으로 해석한다. 예: 2주 뒤, 이틀 뒤, 다음 달 3일, 연도 포함/미포함 월일, 오전/오후 시간. 모호하거나 유효하지 않은 날짜/시간, 날짜와 맞지 않는 요일은 “확인 필요”로 남긴다. 확실한 날짜의 요일은 계산해서 표시한다. 시간이 없으면 “시간 확인 필요”다.
- 템플릿으로 완성한 브리핑을 읽는다. 가족 공유가 켜져 있으면 같은 문구에 개별 전송 확인을 받는다. 연결 실패를 성공으로 표시하거나 자동 재승인하지 않는다. 귀가 인터뷰를 거절하거나 두 번 응답하지 않아도 이미 준비한 진료 메모는 방문 기록에 남기며 새 방문으로 덮어쓰지 않는다.
- 파싱이 확실한 다음 날짜는 기기 내 알림 저장을 별도로 묻는다. 전날/당일 아침에 꺼진 차를 깨우는 기능은 없다. 그 날짜에 서비스가 시작되면 한 번 안내한다. 병원 좌표가 저장되어 있을 때만 길안내 동의를 묻고 `NaviHelper.requestRoute`를 호출한다. POI 검색 API를 가정하지 않는다.

## 운전자 주의 분산과 접근

`CarUxRestrictions`가 알려지지 않으면 제한한다. 서비스의 P와 제한 해제, 화면의 독립 watcher 해제가 모두 충족되어야 메모·브리핑·타임라인·설정·키보드를 연다. 최신 UI 사용자 지시에 따라 주행 중에는 현재 질문, 듣는 상태, n/5와 큰 네/아니요/넘어가 고정 응답만 표시한다. 자유 입력과 HEALTH 동의 터치는 P에서만 받는다. 주행 중 공유 yes는 전체 읽기를 마친 LISTENING 상태에서만 수락한다. 현재 prompt ID가 다르거나 UNKNOWN 기어이면 고정 touch 응답도 차단한다. UI가 잘못 버튼을 노출해도 코어에서 제한한다. CCP는 미지원으로 선언한다.

Pleos 가이드의 반응형 application window, 높은 대비, 큰 터치 영역, 서체 위계를 따른다. portrait 840×1184dp와 landscape 2560×1440/160dpi, 라이트/다크를 지원 대상으로 삼는다. 실제 fit·글꼴 확대·주행 규제는 노트북에서 검증한다.

## 시연과 검증 범위

`--es demo visit`만 release에서 허용한다. 개발 probe/seat 제어 extras는 없다. 시연은 별도 메모리 저장소와 가상 병원 “○○대학교병원”, 호칭 “어머니”를 사용한다. 실제 TTS를 끝까지 말한 뒤 1.8초 후 realistic scripted STT 문자열을 반환하고 “시연: 미리 녹음한 대답”을 항상 표시한다. 미리 녹음한 음성 파일을 재생하거나 실제 마이크 인식을 검증했다는 뜻은 아니다.

기어·도어·UX 제한은 실제 VC 신호다. 다음 버튼은 대화 중 답을 만들지 않고 도착/진료 체류 시간을 진행한다. 시연을 껐다 켜면 가상 기록을 새로 만든다. 실제 기록은 별도 파일에서 복구 선택을 거친다.

시연 시작 시 가족 연결은 `DemoFamilyLink`로 고정하며 실제 HTTP relay를 생성하거나 호출하지 않는다. UI의 명시적인 시연 가족 공유 동의(P+건강 동의) 뒤, 기존 메모/브리핑 읽기와 개별 전송 확인을 그대로 사용한다. 승인된 DTO만 메모리에 보관하고 3초 뒤 “잘 받았어” 답장을 준비한다. 1초 조회 후 코어가 “가족이 잘 받았대요”라고 읽는다. 15분 시연 시간 이동과 별개인 monotonic clock을 사용하므로 “진료 끝”으로 답장 대기까지 건너뛰지 않는다. 정문에서 ParkingMode로 전환한 뒤 시연 패널의 답장 명령 또는 다음 단계는 같은 연결에 “나왔어”를 넣는다. 코어가 OUTSIDE 상태와 고정 안내를 만든다. 가족 동의 철회·전체 삭제·시연 종료 시 대기 답장과 전송 내용은 지워지며 실제 동의 파일·relay에는 어떤 시연 내용도 기록하지 않는다.

시연 캡처 허용의 전제는 실제 기록과의 완전한 분리다. 시연 저장소는 실제 파일을 열지 않고, 과거 기록·진행 중 원문·동의·설정·가족 토큰 모두 초기값에서 시작한다. 전환 시 화면에 남아 있는 입력값도 폐기한다. 실제 모드로 돌아갈 때는 FLAG_SECURE 적용 완료 전까지 빈 상태만 보여 준다. 시연 진입 시에는 두 frame 경계를 기다린 뒤 캡처 차단을 해제해 이전 실제 화면이 교체될 시간을 확보한다(시간 임계값이 아닌 렌더링 순서). 실제 기기의 캡처 결과는 별도 확인한다.

대기열에 남은 화면 명령도 출처 모드가 현재 코어 모드와 같아야 실행한다. 실제 화면의 설정 저장이 시연에 들어가거나, 시연의 삭제 명령이 실제 기록에 적용되지 않는다.
